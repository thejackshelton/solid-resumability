# Solid 2.0 resumability — comptime pass + resume runtime

Can a compile-time pass make *ordinary* Solid 2.0 components interactive without running them, and
without patching solid-js? This repo is the answer, built and measured rather than argued. A
comptime pass reads the analyzer's verdict on each component, emits template / structure / wiring /
per-handler artifacts for the ones it can prove, and refuses the rest by name and code. A small
resume runtime boots served markup against those artifacts: it claims the DOM the build already
painted, wires one delegated listener, and pulls a handler module on the click that needs it.
Resumed components never render; deferred components render late. On the fixtures page that is
**5.50 kB gzip of eager JavaScript (16.12 kB raw) against classic Solid's 12.60 kB gzip / 32.62 kB
raw** for the same page. On the ported TodoMVC it is **14,665 B of eager JavaScript**, with the rest
of the application — four component bodies (two the pass cannot prove, two it proves but may not
substitute), `@solidjs/web`, `@solidjs/signals`, the store and the API — sitting in a **62,331 B
group behind one dynamic import** that no byte of travels until the user touches the page. Both
pages run **zero component bodies before the first interaction**, read live through a loader hook
rather than inferred.

## Layout

Four standalone pnpm projects share this repo and are deliberately *not* a workspace — each has its
own lockfile and installs on its own.

| | what it is |
| --- | --- |
| **`src/`** | the comptime pass (`src/comptime/`), the resume runtime (`src/resume/`) and the coverage tool (`src/coverage/`). The root package is the toolchain |
| **`test/`** | the root suite — classifier, artifact emission, byte parity, cells, see-through props, store model, resume paths |
| **`artifacts/`** | checked-in golden output of `pnpm comptime`. Three suites import it directly; `pnpm comptime` must reproduce it byte-identically, which is how edits to the pass get caught |
| **`app/`** | the byte-frozen corpus: Ryan's own TodoMVC example on Solid 2.0, ported unedited, plus the near-miss fixtures. Read-only to everything else — it is the fidelity anchor, and the coverage number is measured over it |
| **`demo/`** | the measurement instrument. Two variants (classic, resumable) x two pages (fixtures, todos), built **per page** because chunk assignment is per build — a shared build would let one page's graph move the other's bytes. Each target lands in `dist/<variant>/<page>/` with its own manifest, which is what `pnpm measure` reads |
| **`verify/`** | seven witness boxes driving a real Chrome over CDP against the built pages, asserting what the browser actually requested. Needs a sibling checkout of witness at `../witness` (see `verify/README.md`) |
| **`docs/`** | `feasibility-report.md`, the machine-checked `feasibility-citations.txt`, `measurements/` (regenerated by `pnpm measure`) and `coverage/` (regenerated by `pnpm coverage`). Two answers about the world outside this repo live here too: `kobalte/profile.md`, what the pass says about twelve pre-registered Kobalte functions, and `start-mode/answer.md`, whether the plugin composes with `@solidjs/vite-plugin`'s `start: true` |

## Running it, from a cold clone

```sh
pnpm install && pnpm test          # 349 tests, 18 files
pnpm typecheck                     # tsc --noEmit, clean
pnpm comptime                      # regenerates artifacts/ — must diff empty
pnpm coverage                      # rewrites docs/coverage/

cd app && pnpm install && pnpm test        # 30 tests, the frozen corpus's own suite

cd demo && pnpm install && pnpm build      # emits artifacts, builds all four targets
node scripts/check-zero-eager.mjs          # eager caps + frozen group module list
pnpm test                                  # 86 tests
pnpm measure                               # rewrites docs/measurements/

cd verify && pnpm install && node scripts/run.mjs   # needs ../witness; builds it if its dist/ is missing
```

## Pinned

- `solid-js` / `@solidjs/signals` / `@solidjs/web` — all `2.0.0-rc.0`; `@solidjs/vite-plugin`
  `3.0.0-next.28`; `vite` `7.3.6`; `vitest` `4.1.10`; `jsdom` `30.0.1`; `typescript` `6.0.2`.
- `yuku-parser` / `yuku-analyzer` / `yuku-codegen` — exact registry pins at `0.8.5`. The published
  `@yuku-analyzer/binding-darwin-arm64` resolves as an ordinary optional dependency, so there is
  nothing to vendor and no hand-placed `.node`. `test/yuku-smoke.test.ts` proves scopes, symbols,
  references and `capturesOf` all answer.
- No `@dom-expressions/runtime` resolves at all: the DOM runtime ships bundled inside
  `@solidjs/web@2.0.0-rc.0`. The dom-expressions sources the report cites are pinned by commit
  SHA in `docs/feasibility-citations.txt` rather than vendored.

## What holds it honest

- **Verdicts come from the analyzer, never from file names** — `createSignal` destructuring,
  accessor escape analysis, `capturesOf` on inline handlers, static-JSX checks. Fixture A (local
  signal, two handlers sharing it) is proved; Fixture B (signal escapes into an opaque helper) is
  refused. No markers were added to any fixture.
- **Byte parity** — `test/parity.test.tsx` compares classic `render()` output to the template
  artifact with zero normalization: byte-identical, and the DOM returns to the template exactly
  after inc+dec. `test/classic-baseline.test.tsx` is the no-breakage control both paths must pass.
- **Coverage is unflattered** — `src/coverage/` walks `app/src/**` and classifies every module-scope
  component, exported or not. The headline is the `app` segment alone (3 / 5 provable, 60.0%); the
  hand-written fixtures segment is reported separately and never summed into it. That fraction is
  an analyzer verdict and nothing else — one of the three is the component the demo resumes on the
  wire, and the other two are proved with guard-only artifacts whose bodies stay in the deferred
  group. Read it as coverage, never as components resumed.
- **The wire is the referee** — the demo's numbers are re-asserted in a real browser by
  `verify/`, against `encodedDataLength` on the wire, uncompressed, so every total over-counts
  rather than flatters.

**Gotcha:** Solid 2.0 schedules effects — tests call `flush()` from `solid-js` after dispatching
events, or the DOM reads stale.

For the longer story — where this came from, why client-side rendering, what Solid gains, and how
far it could be pushed — see `docs/exploration.md`.
