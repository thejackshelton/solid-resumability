# demo — the same pages, twice, on a scale

Two builds of two pages, plus the harness that weighs them.

|  | `fixtures.html` | `todos.html` |
|---|---|---|
| **classic** | four provable components via `render()` | the ported TodoMVC |
| **resumable** | the same four as inlined template markup + comptime artifacts | the same app with **one** mount point substituted — `Header` is resumed from artifacts, its four siblings render the ordinary way |

The two pages carry two different claims. `fixtures.html` is the **byte** claim: every component
on it is provable, so the framework leaves entirely (−67% eager gzip). `todos.html` is the
**execution** claim: 4 component bodies run where classic runs 5, and `Header`'s keydown handler
arrives as a 397 B chunk on the first keypress — while the page still ships the whole framework
its four other components need, so its eager bytes go *up*. Both numbers are in
`docs/measurements/demo-baseline.md`, neither is adjusted.

```
pnpm install
pnpm test       # writes .measure/executions.json and .measure/todos-executions.json
pnpm build      # emits artifacts, then builds 4 targets into dist/<variant>/<page>/
pnpm measure    # writes docs/measurements/demo-baseline.{json,md}
pnpm dev:classic | pnpm dev:resumable      # both pages, one variant, port 3010 / 3011
```

Run them in that order: `measure` reads a file `test` writes, and refuses to run without it
rather than assume the answer.

## What is where

| path | what it is |
|---|---|
| `fixtures.html`, `todos.html` | the pages — **one** copy each, shared by both variants |
| `build/fixtures.mjs` | the four fixture components and the one app component (`RESUMED`), with their artifact ids; one source of truth |
| `build/substitute.mjs` | the todos page's compiler stand-in: emits `app/src/app.tsx` with `Header`'s body removed and its mount point replaced by a template splice + `resume()` |
| `build/plugins.mjs` | the whole difference between the variants: script swap, template inlining, the API module swap, and the per-module size/code report the measurement reads |
| `build/config.mjs` | the shared build config, and why each page is built alone |
| `src/resume.ts` | the fixtures page's artifact registry — two globs, and the reason `template.js` is not one of them |
| `src/todos-resume.ts` | the todos page's registry, plus the store-action registration hook the substituted mount point calls |
| `src/generated/` | output of `build/substitute.mjs`, regenerated by `pnpm emit` |
| `src/resumable-page.ts` | resume every mount; fall back through a dynamic `import()` for anything with no artifacts |
| `src/classic-page.ts` | `render()` per mount, the ordinary path |
| `src/api-mock.ts` | `app/src/api.ts` minus the 400 ms sleep and the one-in-three random failure |
| `artifacts/` | committed output of `pnpm emit` — regenerated on every build |
| `scripts/measure.mjs` | the byte accounting, and the argument for how it counts |

## The rules this project holds itself to

- **`app/**` is read-only.** The fixture components, the todos app and its stylesheet are
  imported, never edited. One module is *swapped* (`./api`), by resolved path, at build time.
- **Every byte the resumable page fetches before the first interaction is eager**, including
  `@solidjs/signals`, the resume runtime and vite's own preload helper. The HTML is counted
  separately and reported, because the resumable page's markup carries the templates.
- **The one number static analysis cannot produce** — how many component bodies the page runs —
  comes from live loader instrumentation, not from a constant: `test/fixtures-page.test.ts`
  wraps the fixture modules' exports, and `test/todos-resume.test.tsx` wraps
  `@solidjs/web`'s `createComponent`, because four of the app's five components are
  module-local and no export-level hook can see them.

Numbers, and what they do and do not support: `docs/measurements/demo-baseline.md`.
